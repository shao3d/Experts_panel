# Ручная проверка дрифта визуальных каналов, 2026-10-08

Status: Evidence snapshot — production data released
Last updated: 2026-10-09

## Причина и границы

Владелец поручил обновить базу по визуалам. Scoped-синк пяти визуальных каналов и индексация новых постов прошли, но автоматический дрифт через `xiaomi-token-plan-sgp/mimo-v2.6-pro` остановился на `quota exhausted`. Повторы остановили до записи ошибочных решений. Подготовленную staging-БД со свежими постами и VideoHub выпустили штатным режимом `DB_UPLOAD_ONLY=1`; затем владелец отдельно поручил субагенту Sol 6.1 medium разобрать незавершённый дрифт.

Это **разовая ручная проверка**, а не переключение автоматического рантайма. SSOT штатной модели и процедуры — `docs/guides/drift-analysis.md`. Агент работал только со staging и visual-группой; production-БД напрямую не открывал и tracked pipeline не менял.

## Метод и результат

Временный staging-only adapter использовал штатный `DriftSchedulerService` для чтения pending-групп и записи результата. Перед записью он сверял fingerprint исходного поста и комментариев; для каждой темы требовал дословную цитату из комментария. Темы получили embedding через существующий сервис и метку `drift_checked_sol61_manual`. После каждой записи проверялось уменьшение scoped pending на единицу. Временный adapter удалён после проверки.

Все 65 исходных групп и комментарии прочитаны, включая четыре длинных обсуждения по частям. Повторная проверка подтвердила 62 ожидаемых ID, валидность записанного JSON и эмбеддинги для всех 18 групп с дрифтом: размер 768, конечные значения, единичная норма. Среди обработанных групп нет статуса `error`. Всего сохранены 24 отдельные темы. Примеры: экономика автоматизации труда; безопасность запуска JavaScript и раскрытие IP; способ публикации анимаций через GitHub Pages вместо MP4.

На момент первого прохода три группы оставались `pending`: `19511`, `19561`, `19564`. В staging-записях их `media_metadata` пусто, поэтому текстовый анализ не видел вложения. Это было ограничение первого прохода, а не отсутствие оригиналов.

## Production

После первого прохода выполнено отдельное штатное продвижение staging-БД через `DB_UPLOAD_ONLY=1 ./scripts/update_production_db.sh`. Скрипт проверил SQLite, создал backup, атомарно заменил production-БД, перезапустил `panel` и получил успешный `/health` в **22:05 UTC 2026-10-08**. Тогда в production попали 62 проверенных решения; три группы ещё оставались `pending`. Это не меняет автоматический выбор MiMo для будущих циклов дрифта.

## Допроверка исходных вложений, 2026-10-09

Через авторизованную Telegram-сессию прочитаны оригинальные посты и скачаны только три вложения для локальной проверки. `19511` ([Acid Crunch, пост 2887](https://t.me/acidcrunch/2887)) — мем «Тут подают? Вектор», четыре комментария: шутки и реакции на мем. `19561` ([NeuroGraph, пост 4760](https://t.me/neyr0graph/4760)) — 23-секундная AI-сцена с репликой про казино; просмотрены кадры, речь распознана локальным ASR; семь комментариев о сцене, узнаваемости героев и качестве голоса. `19564` ([NeuroGraph, пост 4763](https://t.me/neyr0graph/4763)) — 25-секундная драматическая история с котами; просмотрены кадры; 18 комментариев об эмоциях, музыке, оригинале и технике создания. В последней ветке есть единичная перепалка о качестве канала, но она не образует самостоятельного обсуждения новой темы.

Все три группы после сверки текста и количества комментариев отмечены в staging как `has_drift = false`, `drift_topics = NULL`, `drift_embedding = NULL` с меткой `drift_checked_source_media_manual` через штатный `DriftSchedulerService`. Число `pending` по visual-группе изменилось с 3 до 0. Это разовое решение по просмотренным источникам; автоматический анализатор по-прежнему получает только текст поста и комментарии.

После проверки staging-БД штатный `DB_UPLOAD_ONLY=1 ./scripts/update_production_db.sh` повторно продвинул её в production **2026-10-09**. Проверки целостности SQLite, передача базы и `/health` прошли успешно. В production опубликованы все 65 решений visual-группы, включая три решения по исходным вложениям.
