# Экстракт архитектурных решений из `kdoronin/video_analyzer`

**Дата анализа:** 2026-02-23
**Цель:** Поиск масштабируемых паттернов и инженерных решений для интеграции в проект **Experts Panel (Video Hub)**.
**Формат:** Выжимка лучших практик ("что можно украсть").

---

## 🏗️ 1. Нарезка видео (Chunking)

### 1.1 Паттерн: Semantic Chunking (Нарезка по логике через AI Studio)
Вместо жесткой нарезки длинного видео на равные интервалы (например, каждые 10 минут) или возни с локальными утилитами вроде `ffmpeg silencedetect`, используется нативное понимание контекста длинных видео моделью.
*   **Как работает:** 
    1. Исходное длинное видео (до 1 часа) загружается руками или через скрипт в интерфейс бесплатных квот (Google AI Studio).
    2. Вместо простого вопроса, модели скармливается жесткий XML-промпт, где её просят выступить "Режиссером монтажа". Ии сканирует видео целиком и ищет естественные смысловые паузы (вдох, конец мысли, смена слайда).
    3. Дополнительное жесткое условие: "Никогда не режь мысль посередине, ищи паузы с шагом от 10 до 15 минут". 
    4. Gemini возвращает идеальный JSON-массив из безопасных таймкодов (`["12:45", "26:10", ...]`), по которым файл режется на куски и заливается в БД.
*   **Бизнес-ценность для Experts Panel:** Гарантирует, что сегменты (с нашими `topic_id`) не порвут мысль или слово эксперта пополам. Это решает проблему "рваного контекста" на краях Summary Bridging. Вся магия "понимания тишины и контекста" перекладывается на мощный 2M-контекст Gemini без написания сложного бэкенда.

## 🧠 2. Инженерия Промптов (Prompt Engineering)

### 2.1 Строгие XML-шаблоны
Системные инструкции и контекст передаются моделям не в формате Markdown или плоского текста, а в виде жесткой XML-структуры (например, `<task>`, `<context>`, `<requirements>`, `<output>`).
*   **Зачем нужно:** Современные модели (особенно от Anthropic и новые Gemini) значительно лучше понимают границы инструкций и приоритеты, если они обернуты в XML.
*   **Что дает нам:** Переписывание инструкций "Цифровых Двойников" (в `VideoHubService` и `RedditSynthesisService`) в XML (вида `<persona>`, `<rules>`, `<segments>`) резко повысит процент следования строгим правилам (например, защита от галлюцинаций, "DO NOT SUMMARIZE").

### 2.2 Управление параметрами LLM через бизнес-термины
Внутри XML-промптов для поиска кадров используются сильные инженерные директивы:
*   `<cadence>Ориентир: в среднем один ключевой кадр каждые 10-20 секунд...</cadence>`
*   `<recall_bias>При сомнении включай кадр в выборку, чтобы не терять важный контекст.</recall_bias>`
*   **Ценность:** Такие термины позволяют более предсказуемо управлять поведением модели при парсинге транскриптов.

### 2.3 Meta-Prompting (Автогенерация профилей)
Вместо ручного написания сложных промптов пользователем, вспомогательный скрипт (`PromptGenerationService`) принимает простое текстовое описание задачи (например, *"Оцени кандидата на собеседовании"*) и **генерирует идеальный, размеченный XML-шаблон** под конкретную модель (Gemini/OpenRouter).
*   **Применение у нас:** Идеально подходит для упрощения онбординга новых экспертов. Оператор пишет 2 абзаца текста (кто такой эксперт, в чем он силен), а внутренний AI-вызов генерирует сложный, идеально отформатированный XML-профиль (System Prompt) для базы данных.

## 🖼️ 3. Мультимодальность и Визуал

### 3.1 Smart Keyframes (Двухэтапная экстракция контекста)
Разделение процесса на логический и физический уровни.
*   **Шаг 1 (AI Logic):** LLM анализирует кусок видео в AI Studio и выплевывает строгий JSON-массив из важных таймкодов и детальных описаний того, что нарисовано на экране.
*   **Внедрение в Video Hub:** Огромный потенциал для улучшения UX. Выдача в React-фронтенд (наш роскошный Sidebar) может стать мультимедийной. Вместо сухого текста пользователь получит в компоненте `PostCard.tsx` референсы к тому, на какой минуте видео эксперт рисовал какую схему.

## ⚙️ 4. Отказоустойчивость и Инфраструктура

### 4.1 Паттерн Exponential Backoff + Jitter
Сетевые вызовы к LLM-провайдерам обернуты в умный `retry`.
*   При получении ошибки HTTP 429 (Too Many Requests), скрипт ждет 2 секунды (плюс случайная дельта — Jitter), затем 4, затем 8 секунд, прежде чем сдаться (до 5 попыток).
*   **Критичность для нас:** Наш пайплайн в `simplified_query_endpoint.py` использует конкурентные вызовы (Map Phase). При масштабировании или запуске тяжелой генерации (Summary Bridging), мы неминуемо упремся в лимиты API Gemini Studio. Этот паттерн нужно оборачивать в декоратор и применять к нашему `google_ai_studio_client`.

### 4.2 Программная фильтрация моделей
Вместо конфигурации моделей только через статичные ENV-переменные, классы-анализаторы (Gemini/OpenRouter) могут опрашивать API провайдера (`/models`) и проверять, поддерживает ли модель `video`/`multimodal` в поле `input_modalities`.
*   **Польза:** Задел на будущее. Если мы будем реализовывать админку для выбора LLM под разные фазы пайплайна (Map, Reduce, Synthesize), такая фильтрация защитит оператора от запуска тяжелой "визуальной" задачи на легковесной текстовой модели (вроде `Mistral` или `Llama-3`).

### 4.3 Архитектурный выбор: Files API vs Base64 Stream
*   **Base64 (как в OpenRouter):** Кодирует видео прямо в тело запроса. Лимит (открытых API) — 20MB. Идеально для пары скриншотов, но не для видео.
*   **Files API (как в Gemini):** `client.upload_file() -> PROCESSING -> ACTIVE -> generate_content()`. 
*   **Вывод:** Наш выбор хранить логику в AI Studio (асинхронная загрузка, кэширование видео на их серверах) абсолютно правильный для тяжелого B2B-продакшена (как у Experts Panel), так как попытки лить видеопоток прямо в API-вызовы невероятно хрупки и дороги.
